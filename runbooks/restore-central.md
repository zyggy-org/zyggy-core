# restore-central.md — rebuild Central from its snapshot

Placeholders only (`acme`, `central`, `<zyggy-home>`, `<vm-admin>`); every command prefixed with the machine and the user. The instance's evidence of a real restore goes to its private repository.

1. `[central/<vm-admin>]` New VM from the volume snapshot; the same hostname, the same `zyggy` user and uid; `/opt/zyggy/<version>/` and the two symlinks per `install-node.md` (the snapshot may carry them already — check `zyggy --version` and `zyggy-node --version`).
2. `[central/zyggy]` `claude login` state: `claude -p "say ok"` must answer without a browser prompt; otherwise log in again as `zyggy` (the node refuses to start with `claude not logged in` until then).
3. `[central/zyggy]` The deploy keys: the two read-only keys of the core and memory repositories and the write deploy key of the bus, with their `~/.ssh/config` aliases (`Host github.com-zyggy-bus` → `IdentityFile ~/.ssh/zyggy_zyggy-bus_ed25519`, `IdentitiesOnly yes`); `ssh -T git@github.com-zyggy-bus` answers with the repository name. A key that is gone is replaced on GitHub, never recovered from a copy.
4. `[central/zyggy]` `zyggy-core` into the Central working directory and the memory repository next to it (the template README "Create an instance"); `.claude/settings.local.json` from `instance/`; the user-scoped `~/.claude/settings.json` with the `Read` and `Edit` deny rules for `<zyggy-home>/.local/share/zyggy/secrets/**` (deliverable 10 sets them by hand; 15's template ships them). The deliverable-27 verification of the instance passes.
5. `[central/zyggy]` The secrets, re-entered — never restored from a copy of the files: `zyggy secret set hmac/<n> --hex` (the tenant's key, at the hidden prompt; compare the fingerprint with a laptop's `zyggy secret list`) and `zyggy secret set github-pat`; `zyggy secret list` shows `hmac/<n> … signs`. If the credentials drop-in was in use, re-create `/etc/systemd/system/zyggy-node.service.d/credentials.conf` as `<vm-admin>` (`install-node.md`, "Bus secrets").
6. `[central/zyggy]` The bus checkout at `bus.localPath`: `git status` clean, on `main`, `tenants/acme/` present; `zyggy verify` → `0 failed`.
7. `[central/<vm-admin>]` The units, in order: `claude-remote`, `zyggy-node`, then the dream, brief and m365 units; `systemctl is-active` for each. The clone cache is not restored — it refills on demand.
8. `[central/zyggy]` `zyggy status` → `health: green`; the laptops' `zyggy status` show Central's reports again within one poll interval. Record the restore date and the snapshot id in the instance's private repository.
